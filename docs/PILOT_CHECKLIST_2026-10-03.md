# Short core checks, then actual lessons
Owner: Codex prepares checks; teacher runs actual devices/classes.
Date: 2026-10-03. Do not treat this checklist as evidence that it has been completed.

## Before the first real lesson
Use synthetic records for the short technical checks. Keep a current encrypted backup of real records before an app update.
Record device, app version/commit, language, date and pass/fail with a brief reason.

| Flow | Check | Evidence to record |
|---|---|---|
| Start | Pick class, start, open attendance/fitness, return | Time/actions, class remains correct |
| Save | Record a legitimate zero and another result, close/reopen | Exact values, stable pupil identity |
| Identity | Two pupils with same name; rename a class | Separate histories, no lost results |
| Pupil profile | Open missing tests with another Fitness class selected | Own class list, basis visible, not final grade |
| End | Finish with or without a note | No mandatory reflection, saved results remain |
| Prepare | Ready plan and manual assembly; edit duration/equipment | No blocked save/start, useful timing summary |
| Language | New install English; change language/reopen | Choice retained, teacher-entered data unchanged |
| Recovery | Encrypted file to separate test context; wrong password | Correct restoration; wrong password changes nothing |
| Android update | Install newer APK over old test install | Records survive without uninstall |

For missing tests, the implemented first slice uses class-recorded fitness tests plus the existing fitness-index selection. Per-class/per-period requirements and other report-card components remain follow-up work.

## Field/device checks
Use the existing native-device script in docs/PE_ULTIMATE_PLAY_READINESS_2026-09-29.md. Record actual phone results separately from browser emulation: sunlight/touch, keyboard/back, camera permission refusal/recovery, audio/silent switch, file share/cancel, background/reopen and app upgrade. Apple testing awaits the owner's Mac/devices.

## Actual teaching after the short checks
Try ordinary lessons in a few of the teacher's classes. For each lesson, record only:
- Did a blocked or failed action interrupt teaching? What happened?
- Which phone action took too long or required repeated choices?
- Was the plan feasible with the actual pupils/equipment/time?
- Did the missing summary help decide what to measure next?
- Did reopening/reusing the lesson preserve the expected records?

Optional quick rating plus optional note is the intended future feedback flow, not a required form. Fix repeated reliability/friction problems before adding more modules. Teacher validation of instructions/timing and native-language review remain distinct from automated checks.
